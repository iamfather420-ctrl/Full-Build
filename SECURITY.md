# Security Policy

## Supported versions

Security fixes are applied to the current default branch. Older releases and branches are not guaranteed to receive security updates. If you rely on a release or deployment, identify its exact commit when reporting an issue.

## Reporting a vulnerability

**Do not report suspected vulnerabilities in public issues, discussions, or pull requests.**

Use GitHub's **Private vulnerability reporting** for this repository, if enabled, or contact the repository maintainers privately through GitHub to request a secure reporting channel. Include:

- A concise description and potential impact.
- The affected commit, release, component, and configuration.
- Reproduction steps or a minimal proof of concept.
- Any logs or artifacts with secrets, tokens, personal data, and customer data removed.

Do not access, modify, or retain data that does not belong to you. Do not perform denial-of-service testing or otherwise disrupt services.

## Response expectations

The maintainers will acknowledge reports as soon as reasonably practical, assess severity and reproducibility, and coordinate remediation and disclosure with the reporter. Please allow time for investigation and a fix before public disclosure.

A report is not authorization to test production systems. Use an isolated, non-production environment unless you have explicit written permission.
