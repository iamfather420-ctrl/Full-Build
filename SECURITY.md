# Security Policy

## Supported versions

The current default branch, `main`, is the maintained development line.

Older commits, snapshots, and archived source bundles are not separately supported. No additional release-support window is currently declared.

## Reporting a vulnerability

Please do not report suspected vulnerabilities in public issues, pull requests, discussions, or other public channels.

When GitHub private vulnerability reporting is enabled for this repository, use the repository's **Security** tab and select **Report a vulnerability** to submit a private report.

If that private reporting option is unavailable, contact the repository owner through an established private channel before sharing technical details. Do not publish exploit details or sensitive evidence.

## What to include

- A concise description and potential impact.
- Affected commit, branch, version, file, or endpoint.
- Reproduction steps and the minimum proof needed to validate the issue.
- Any known mitigations.

Please avoid accessing, modifying, or deleting data that does not belong to you while investigating. Do not run destructive tests against production systems.

## Response

Reports will be reviewed as resources permit. This policy does not promise a fixed acknowledgement or remediation deadline. Please allow time for validation and coordinated remediation before any public disclosure.
